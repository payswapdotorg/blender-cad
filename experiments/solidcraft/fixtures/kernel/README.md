# Kernel benchmark fixtures (experiment C — Task 100, W2 lane b)

Shared fixture set for the comparative kernel experiment: SolidCraft's vendored-patched
`truck` kernel (through `solidcraft-kernel` at the pinned upstream SHA) vs OCCT 8.0.1
through the `cadquery-ocp` 8.0.1.1.0 Python wheels (OCP venv outside the repo tree, experiment-side only).

**16 fixtures: 10 upstream-oracle-derived + 6 self-authored.** Machine-readable metadata
with per-case provenance and analytic expectations: [`cases.json`](cases.json). CLI timing
scripts (one per fixture, the release-binary input format): [`scripts/`](scripts/).

The same parts are implemented twice, from the same parametrization:

- truck side: `harness/src/bin/w2_kernel.rs` (direct `solidcraft-kernel` API, pinned
  clone `.upstream` @ `3b4db52`, vendored patched truck — the kernel SolidCraft ships);
- OCP side: `python/ocp_kernel_bench.py` (OCCT via OCP bindings, OCP venv outside the repo tree).

## Provenance rules (experiments/solidcraft/README.md §1.4)

- Upstream-derived cases record: upstream path (`tests/oracle/<case>`), pinned SHA,
  `recipe.json` SHA-256, license (MIT OR Apache-2.0), and the expected-value source
  (`analytic` closed-form or `freecad <version>` = FreeCAD/OCCT-built). Expected values
  are copied **verbatim** from upstream `expected.json` — none were re-measured.
- The CLI script of each upstream-derived case was generated by the official release
  binary itself (`solidcraft-cli recipe tests/oracle/<case>/recipe.json`; tag v0.16.2 =
  `5de48e9`, measured 80 commits behind the source pin) and its SHA-256 is recorded.
- Self-authored cases state author + date and carry self-derived analytic expectations
  with the formula in `expected.method`:
  - `k07b-fillet-4-vertical` — same box as oracle 07, fillet on the 4 vertical edges only;
  - `st1-fillet-too-large`, `st2-near-tangent-cut`, `st3-thin-sliver-extrude`,
    `st4-coincident-face-union`, `st5-near-tangent-sphere-union` — the robustness stress
    set (refusal, near-tangency, sliver, coincidence).

## Comparability labels

Every case carries one label with a one-line reason (`cases.json` → `comparability`):

- `comparable` — planar/analytic parts where both kernels are judged independently
  against the same closed-form ground truth (box, cylinder, booleans with analytic totals).
- `approximately-comparable` — same part, same analytic totals, but kernels build
  different by-design local geometry (fillet corner patches, chamfer miters, revolve seam
  splitting, shell algorithm differences). Cross-kernel deltas on these are recorded as
  observations, never verdicts. Upstream's own oracle README notes the same for
  FreeCAD-built corner shapes.
- Robustness cases are judged by outcome class: `success` / `refused-with-error`
  (verbatim text recorded) / `wrong-result` (vs analytic). A clear refusal is an honest
  outcome, not an automatic loss.
