## 1. Isolation rules (binding for every experiment here)

1. **Nothing in this directory is product code.** No import from `experiments/` may appear
   in `modules/`, `scripts/`, `tests/` (repo root), or the extension build. Nothing here
   changes the shipped extension, the document schema, the kernel direction, the CAD tool
   contract, packaging or the release manifest.
2. **The upstream repository is never vendored into git.** `fetch-upstream.sh` clones the
   pinned SHA into `.upstream/` (gitignored). Committed evidence records the SHA; the
   clone is reproducible from the script.
3. **No production runtime dependency may be introduced as a side effect.** The Rust
   harness is a dev-time experiment workspace; the OCP venv (`solidcraft-ocp-venv/`, gitignored) is
   an experiment-side comparison environment, not a product dependency.
4. **Fixtures carry provenance.** Self-authored fixtures state author + date; fixtures
   derived from upstream files (e.g. `recipe.json` oracle cases) record the source path
   and the pinned SHA they were copied from (MIT OR Apache-2.0, attribution preserved).
5. **Results are machine-readable and committed** (`results/*.json`), generated by the
   scripts in this tree, never hand-edited. Each result file embeds the generator
   command, the upstream SHA, timestamps and environment facts.
6. **Failures are recorded, never silently dropped.** An experiment that cannot complete
   records its blocker in its result JSON and in the evaluation doc.

## 4. Reproduction (from a clean sandbox)

```bash
# 1. upstream clone at the pinned SHA
./experiments/solidcraft/fetch-upstream.sh
# 1b. official release binary for the MCP PoC (experiment D)
./experiments/solidcraft/fetch-release.sh
# 2. Rust toolchain (>= 1.95; 1.99.1 used for recorded results)
rustup toolchain install stable
# 3. warm build of the harness crates (geom/sketch/kernel/doc; NEVER build the GPU/UI app)
#    -j 1 is mandatory on the 2-CPU/4GiB-cgroup sandbox (parallel rustc OOM-kills)
cd experiments/solidcraft/harness && cargo build --workspace -j 1
# 4. OCP comparison environment (experiment-side only)
python3.12 -m venv /home/z/solidcraft-ocp-venv && /home/z/solidcraft-ocp-venv/bin/pip install cadquery-ocp==8.0.1.1.0
# 5. run a specific experiment (see its result JSON for the exact command)
cargo run --bin w2_history   # example
```

Sandbox constraints recorded honestly (Task 96 bootstrap):

- `solidcraft-engine` / `solidcraft-mcp` cannot be linked into the harness here:
  they pull `solidcraft-io` → `cadmpeg-ir`, whose rustc codegen exceeds the 4 GiB
  cgroup limit (peak > 2.4 GB at SIGKILL, opt-level 0, `-j 1`). Experiment D uses
  the checksum-verified official release binary instead — the shipped MCP server,
  which is the integration seam a real agent would face. Release tag `v0.16.2`
  (commit `5de48e9`) is 80 commits behind the source pin `3b4db52`; source audits
  use the pin, behavioral MCP evidence uses the binary, and every result file says
  which.

## 5. Build-profile fidelity (why the harness Cargo.toml looks like it does)

The harness replicates upstream's `[patch.crates-io]` table (vendored, SolidCraft-patched
`truck-geometry` / `truck-shapeops` / `truck-stepio` / `truck-meshalgo` / `matext4cgmath`)
so experiments run against **the kernel SolidCraft actually ships**, not stock crates.io
truck. The `egui-wgpu` patch is intentionally NOT replicated: no experiment builds the UI.

Upstream's dev profile optimizes dependencies at `opt-level = 2` and disables
debug-assertions (truck's debug-only checks reject valid geometry — upstream comment in
their `Cargo.toml`); the harness replicates both. Timing-sensitive experiments
(experiment C) run `--release` (upstream release profile: opt-level 3, thin LTO).

The harness `Cargo.lock` is seeded from upstream's `Cargo.lock` on first fetch (see
`fetch-upstream.sh`) so dependency versions match the upstream-tested set.

## 6. Evidence provenance

Every committed result records, at minimum: the upstream SHA, the harness git commit,
the exact command line, wall-clock timestamps, host facts (CPU count, memory), and the
raw measurements. See `results/README.md` for the shared JSON schema.
