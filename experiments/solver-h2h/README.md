## 2. Isolation rules (binding for every experiment here)

The m3-eval lane rules apply verbatim
([experiments/cad-sketcher/README.md §1](../cad-sketcher/README.md)); restated
in force here:

1. **Nothing in this directory is product code.** No import from
   `experiments/solver-h2h/` may appear in `modules/`, `scripts/`, `tests/`
   (repo root), or the extension build. Nothing here changes the shipped
   extension, the document schema (`bcdoc` stays authoritative — experiment-B
   seam is the integration architecture, design-locked by m3-eval), the kernel
   direction (ADR-0002), the CAD tool contract, packaging or the release
   manifest.
2. **Upstream is never vendored into git.** `fetch-planegcs.sh` (FreeCAD 1.1.4
   tag pin, sha-verified), `fetch-eigen.sh` (eigen 3.4.0 orig tarball,
   sha256-pinned) and `fetch-solidcraft.sh` (tangency-labs/solidcraft @
   `3b4db52` — TL2's exact pin) materialize into `.upstream/` (gitignored).
   The `compat/` headers committed here are OUR OWN evaluation-only shims
   (null-sink Console stubs), marked as such in every file.
3. **No production runtime dependency may be introduced as a side effect.**
   Scratch builds live under `.upstream/` + `scratch/` (gitignored) or outside
   the repo (`/home/z/solver-h2h-scratch/`); the toolchains (rustup, cargo)
   install outside this tree.
4. **Fixtures carry provenance** — and the canonical corpus is READ-ONLY here:
   it is m3-eval-owned (`experiments/cad-sketcher/fixtures/solver/cases.json`,
   generated by their `gen_solver_cases.py`, never hand-edited). This lane
   CONSUMES it; any gap discovered is recorded as a finding, not edited around.
5. **Results are machine-readable and committed** (`results/*.json`), generated
   by the drivers here, never hand-edited, each embedding the exact command,
   pins, timestamps and host facts (mirroring the m3-eval/TL2 envelope schema).
6. **Failures are recorded, never silently dropped** — an import failure,
   an unbuildable artifact or an API gap is a FINDING with its evidence, not a
   task failure; result JSONs carry `failures` sections.

## 4. Reproduction (from a clean sandbox)

```bash
# prerequisites: g++ >= 13 (C++20; sandbox has 14.2), system boost >= 1.75
# (sandbox has 1.83), cargo (via rustup, outside the repo), python3
./experiments/solver-h2h/fetch-planegcs.sh
./experiments/solver-h2h/fetch-eigen.sh
./experiments/solver-h2h/fetch-solidcraft.sh
# PlaneGCS side
./experiments/solver-h2h/planegcs-side/build.sh
python3 experiments/solver-h2h/planegcs-side/gen_planegcs_results.py
# SolidCraft side
./experiments/solver-h2h/fetch-solidcraft.sh   # seeds Cargo.lock after first cargo run
(cd experiments/solver-h2h/solidcraft-side && cargo run --release -- <mode>)
python3 experiments/solver-h2h/solidcraft-side/gen_solidcraft_results.py
```

## 5. Evidence provenance

Every committed result records, at minimum: the upstream pin(s) + SHA, the exact
command line, wall-clock timestamps, host facts, and the raw outputs. License
quotes in `findings/` carry file paths (+ line numbers where stable) and the
tag/SHA they were read from. The slvs reference numbers (m3-eval) and TL2's
w1-sketch numbers are cited by commit; the head-to-head re-runs BOTH sides on
the SAME corpus in THIS lane so no cross-lane timing/environment drift
contaminates the comparison.
