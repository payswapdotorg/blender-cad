## 2. PlaneGCS is LGPL-family, "or later", at every file — verbatim

All 11 files under `src/Mod/Sketcher/App/planegcs/` at the FreeCAD 1.1.4 pin
carry the same header block (machine-verified per file; the envelope embeds
each file's verbatim header + sha256). From `GCS.h:2-8`:

> /***************************************************************************
>  *   Copyright (c) 2011 Konstantinos Poulios <logari81@gmail.com>          *
>  *                                                                         *
>  *   This file is part of the FreeCAD CAx development system.              *
>  *                                                                         *
>  *   This library is free software; you can redistribute it and/or         *
>  *   modify it under the terms of the GNU Library General Public           *
>  *   License as published by the Free Software Foundation; either          *
>  *   version 2 of the License, or (at your option) any later version.      *
> ```

`Geo.cpp` adds a second author with the same license block:
`Copyright (c) 2014 Victor Titov (DeepSOIC) <vv.titov@gmail.com>` (the
conic-constraint extension), keeping the identical LGPL wording.

**Classification (conservative, recorded for the inventory):**

- The per-file wording is the legacy "GNU **Library** General Public License …
  either **version 2** of the License, or (at your option) any later version"
  — in modern SPDX terms this form reads as **LGPL-2.0-or-later**.
- The FreeCAD **project-level** license is **LGPL-2.1-or-later**: the root
  `LICENSE` at the pin is the full GNU LGPL **2.1** text (26,526 chars,
  machine-verified head: `GNU LESSER GENERAL PUBLIC LICENSE / Version 2.1,
  February 1999`), and sibling files at the same pin carry modern SPDX tags —
  `src/boost_graph_adjacency_list.hpp:2` (the 11-line boost ≥1.75 workaround
  planegcs includes) says verbatim:
  > `// SPDX-License-Identifier: LGPL-2.1-or-later`
- `src/Mod/Sketcher/SketcherGlobal.h` (Werner Mayer 2019; vendored read-only
  by the build, never modified) carries the same legacy LGPL header.
- **Both readings are LGPL-family with an "or later" clause**, so combined
  distribution with a GPL-3.0-or-later host is available either way; the
  inventory row records the wording ambiguity explicitly rather than
  flattening it. Practical obligations (either reading): retain the license
  text, keep the library boundary (LGPL §4-style), permit user relinking for
  the vendored object — none of which differs in kind between 2.0-or-later
  and 2.1-or-later for our packaging path.

- **Provenance constraint, honestly recorded:** Eigen's canonical repo
  (`gitlab.com/libeigen/eigen`) is **intermittently unreachable from this
  sandbox** — m3-eval hit 403 on every path (§7.2/§9); this lane's first
  retest succeeded (ls-remote AND a full depth-1 fetch of the 3147391d pin),
  and a subsequent ls-remote 403'd again within the same session. The pin for
  THIS lane's build is therefore the Debian-pool mirror of the **upstream
  3.4.0 release tarball** (byte-exact upstream artifact, sha256-pinned,
  reproducible via `fetch-eigen.sh`) — which is also the version line FreeCAD
  1.1.4 itself requires (`cMake/FreeCAD_Helpers/SetupEigen.cmake`:
  `find_package(Eigen3)` marked *"necessary for Sketcher module"*; flatmesh
  requires ≥ 3.4.0).
- The planegcs build compiles against MPL2-only Eigen headers by construction:
  the TUs include `<Eigen/QR>` / `<Eigen/Dense>` core paths; if the packaging
  review later requires belt-and-braces, `-DEIGEN_MPL2_ONLY` is the upstream
  mechanism to *enforce* MPL2-only includes at compile time (upstream's own
  recommendation, quoted above).
