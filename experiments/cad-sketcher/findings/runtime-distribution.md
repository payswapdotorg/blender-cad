  Verdicts are TL-owned. Evidence: `results/runtime-distribution.json` (generated by
  `scripts/gen_runtime_distribution.py`, never hand-edited; cross-checks the Phase 1
  envelopes and re-measures ldd/footprint).
- **Pin:** CAD Sketcher v0.32.1 (`e7db7e6…`); solver `slvs-3.2` cp313 manylinux wheel,
  sha256 `9ee04ff5…` (byte-identical to PyPI).

## 1. Platform matrix vs OUR five target platforms

Our targets (from the OCP row evidence, `kernel-bindings-evaluation-m1.md`):
macosx_11_0_arm64, macosx_11_0_x86_64, manylinux_2_28_aarch64, manylinux_2_28_x86_64,
win_amd64. CAD Sketcher's manifest declares `windows-x64, macos-x64, macos-arm64,
linux-x64` (`blender_manifest.toml` platforms list); the committed wheels are cp311+cp313
× {macosx_10_12/10_13_x86_64, macosx_11_0_arm64, manylinux_2_17_x86_64,
musllinux_1_2_x86_64, win_amd64}.

| Our target | Covered | Note |
|---|---|---|
| macosx_11_0_arm64 | ✅ | macosx_11_0_arm64 wheels (both ABIs) |
| macosx_11_0_x86_64 | ✅ | cp313 uses macosx_10_13_x86_64 (min-macos 10.13 — covers 11.0) |
| manylinux_2_28_x86_64 | ✅ | manylinux_2_17 wheels satisfy the 2.28 baseline (glibc 2.17 ≤ 2.28) |
| win_amd64 | ✅ | win_amd64 wheels |
| **manylinux_2_28_aarch64** | ❌ **MISSING** | **no aarch64 Linux wheel ships at all** — the concrete gap for us; a hypothetical adoption would require building an aarch64 `slvs` wheel from solvespace @ `477d4c8` (its CI matrix would also need an arm64 Linux job) |

Python ABI: cp311 + cp313 only — no cp312, which is fine (Blender embeds 3.11 ≤ 5.1 and
3.13 ≥ 5.2; our pin is 5.2.2 / 3.13.13). The addon docs' "3.11, 3.12 and 3.13" refers to
PyPI `slvs` availability for source installs, not the bundled set.

## 2. Sizes and native requirements

- Release ZIP (linux_x64): 13,968,966 B (sha256 `c679cccd…`, Phase 1).
- Committed wheels: 10 files, 14,880,583 B total (cross-checked against the Phase 1 audit
  inventory); per-wheel sizes in `results/runtime-distribution.json` (manylinux cp313
  2,861,309 B; musllinux cp313 3,797,388 B; macos ~280 KB; win ~286 KB).
- Installed footprint (measured on the Phase 1 scratch install): **17,022,892 B (16.2 MiB)**,
  of which wheels 13,257,604 B (the linux_x64 ZIP carries FOUR wheels: cp311+cp313 ×
  manylinux+musllinux).
- Native deps (`ldd` on the pinned `solvespace.so`): only standard glibc runtime —
  `libpthread, librt, libstdc++, libm, libgcc_s, libc` (+ vdso/ld). No libgomp (OpenMP
  off in the wheel build), no separate Eigen/mimalloc libraries — both are compiled in
  (Phase 1: `FORCE_VENDORED_Eigen3=ON`, `mimalloc-static`). Tag `manylinux_2_17` →
  glibc ≥ 2.17; a `musllinux_1_2` variant exists for musl systems.

## 3. Startup impact

Phase 1 measured (isolated BLENDER_USER_RESOURCES, 3 runs each, medians):
`blender --background` startup 0.539 s without vs 0.664 s with the extension enabled —
**+0.125 s median** (`results/runtime-compat.json`; not re-measured — the Phase 1 protocol
stands).

## 4. Error-handling surface

- **Solver level** (Phase 2a): result flags `OKAY / INCONSISTENT (== internal
  REDUNDANT_DIDNT_CONVERGE) / DIDNT_CONVERGE / TOO_MANY_UNKNOWNS / REDUNDANT_OKAY` + dof
  + a bad-constraint handle list that is a *failure-point* report, NOT a complete
  conflict/redundancy diagnosis (measured: W1-redundant fixture fails outright).
  No residual or iteration surface is exposed. Guards inside the binding **abort the
  process** on invalid API use (`Platform::FatalError`), so an integration must validate
  inputs before calling the solver.
- **Addon level**: flags map to user-facing states incl. a `REDUNDANT_OK` info state
  (`global_data.py:60-110`); failed solves mark per-constraint `failed` flags for the UI
  (`curve_solver.py:329-361`); implied-redundant constraints are gated OUT of the solver
  by policy (issue #674, `curve_solver.py:335-352`); operators report with
  `self.report({'WARNING'}/{'ERROR'}, …)` strings and `{'CANCELLED'}` (e.g. `solve.py`
  "Solver failed"; the extrude tool's pre-validated
  "Select a sketch or curve to extrude (2D profile)", `operators/modifiers.py:755`).

## 5. Distribution obligations (facts only — TL owns verdicts)

Hypothetical distribution of the addon's wheel set would require: GPL license texts
(addon GPL-3.0-or-later manifest; solver **GPLv3-or-later with NO linking exception** —
Phase 1 verbatim evidence), **corresponding source** for the shipped binaries
(solvespace @ `477d4c8` incl. the Eigen @ `3147391d` and mimalloc @ `f81bf1b` submodule
pins), notice preservation, and GPL-3.0-or-later combined-work terms (ADR-0005 context).
Two standing traps (Phase 1, unresolved): the slvs wheel **METADATA claims MIT while
shipping a GPLv3 COPYING.txt** — pip-metadata scanners mis-report; and the solvespace
`v3.2` tag has drifted (PyPI artifacts pin to `477d4c8` via the sdist's embedded git
refs). Update-channel model: extensions.blender.org listing (human moderator approval)
plus self-hosted `stable/latest` index.json channels
(`hlorus/CAD_Sketcher-extensions`; release.yaml `publish-stable` job) — wheels are never
rebuilt by CI, they are committed in-repo and byte-identical to PyPI.

## 6. Explicit non-changes
